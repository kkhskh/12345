# Frozen protocol and fresh confirmation (Workstream D)

Investigation XIII, Phase 1.5 Step 1.

## 1. Two-stage freeze

**Stage 0** (`STAGE0_PROTOCOL_FREEZE.md`, commit `96c05e8`, `logs/STAGE0_HASHES.txt`) was committed before any cohort job. It fixed:
- the pool P160–P165, with no replacements;
- readiness-gated P-count pretraining (aux_acc ≥ 0.99, at most 2 continuation blocks);
- one `full_c1` fine-tune of every parent (seed 20, 4000 steps);
- the development/confirmation boundary.

**Stage 1, the prediction freeze** (this section, `logs/FREEZE_XIII_HASHES.txt`) was committed **before any T4 fine-tune of the cohort
started**. At that point, pretraining of the first parents had finished or was running. Pretraining contains no T4 information. It fixes:
- the predictions, with thresholds, units, pass rules and nulls, in `logs/predictions_xiii.json`;
- the scorer, `scripts/score_xiii.py`;
- every analysis script and its stream;
- the training and confirmation queues, `logs/queue_train_T*.txt` and `logs/queue_conf_C*.txt`, generated by
  `scripts/make_conf_queues.py`;
- the merge script, `scripts/conf_merge.sh`;
- the scorer preflight, `scripts/preflight_nulls.py` → `logs/preflight_nulls_result.json`.

**Single source of truth.** The prediction table below is rendered from the same JSON that the scorer evaluates
(`scripts/render_predictions.py`). This removes XII's text/code divergence defect.

**No outcome blindness is claimed.** The author designed both the predictions and the analyses, and selected the development thresholds
after seeing development results. What is protected is that confirmation models are fresh: new seeds and new analysis streams
(74_000_000 and above), none seen before the freeze.

**Amendment policy.** There are no amendments after the freeze. Any departure from the frozen protocol, such as a crash, a rerun, or a
changed command, is recorded under *Deviations* and in `logs/COMPUTE_LOG.txt`. A prediction affected by a deviation is reported as
*inconclusive (deviation)*, not as passed.

## 2. Pre-freeze fixes found by development and preflight (all before the freeze, all logged)

1. **J_H pair contrast was off-support.** Under β = 1, editing one colluder group's values breaks the colluders' identity, so the edited
   episode has probability 0 and the exact posterior is NaN. It was replaced by the S = 3 (J_H-dependent) slice
   (`MATHEMATICAL_SUFFICIENCY_AND_GENERALIZATION.md` §C2).
2. **`optax.masked` did not freeze parameters.** In `adapt_sel.py` it passes raw gradients through for masked-out leaves, so in the first
   development run the readout, attention and MLP conditions diverged to NaN or below-chance accuracy. It was replaced by
   `multi_transform` with `set_to_zero`, and a `frozen_params_unchanged` check was added to every condition's output. Steps were reduced
   from 1500 to 1000 for compute.
3. **Degenerate fidelity R².** When the observed change is identically zero (a no-op), R² evaluated to 1.0. It now returns 0.0 in every
   `fid()`. Found by the scorer preflight.
4. **Decoy discrimination was dominated by one stratum.** Discriminating pairs were 99.85% E≠PERM. They are now stratified: 1000 E≠A1
   pairs and 1000 E≠PERM pairs, reported separately.
5. **A degenerate pass in P2b.** The arm "decoy NIE ≤ 0.4 × mixture NIE" passed when both were 0. It now also requires mixture NIE ≥ 0.2.
   Found by the preflight.

## 4. Frozen predictions

Mixture-class rule (frozen): a parent is mixture-class iff some layer-2 head has readout-token attention mass on the target question's six source tokens >= 0.8 AND direct-logit variance share >= 0.2 (l2_scan).

Pass rule: an arm passes if its test holds in >= ceil(0.75 n) units (n >= min_units, default 2; otherwise INCONCLUSIVE). A prediction is CONFIRMED iff all its arms pass. An arm with a null is DIAGNOSTIC only if the null fails on every unit; a passing arm whose null passes anywhere is NON-DIAGNOSTIC.

## 5. Scorer preflight against null scenarios

`scripts/preflight_nulls.py` constructs four null units whose outputs follow from the scenario:
- NOOP: no intervention changes the output;
- UNIFORM: uniform output;
- RANDOM: unrelated output changes;
- ALTMECH: the network implements the perfect-only (A1) mixture instead of E.

The requirement is that **no primary prediction (P1–P5, P8) is confirmed by any single null unit**.

**Result: OK.** No primary prediction is confirmed by any null unit.

Arm-level passes on null units mark arms that do not discriminate against that null on their own. Each such prediction is protected by
its other arms:

- P1a passes on NULLALTMECH
- P2b passes on NULLALTMECH
- P3b passes on NULLNOOP
- P3b passes on NULLUNIFORM
- P3b passes on NULLRANDOM
- P4b passes on NULLALTMECH
- P5a passes on NULLNOOP
- P5a passes on NULLUNIFORM
- P5a passes on NULLRANDOM
- P5a passes on NULLALTMECH
- P5c passes on NULLNOOP
- P5c passes on NULLUNIFORM
- P5c passes on NULLRANDOM
- P8b passes on NULLALTMECH
- P8c passes on NULLALTMECH

**P7** is correlational: it does not intervene. It passes on the null units where attention structure is kept
(NULLNOOP, NULLUNIFORM, NULLRANDOM, NULLALTMECH). It can therefore only ever be **supporting** evidence, and it is
reported as non-diagnostic with respect to interventions.

**Development scoring** of the same scorer (`SCORE_SFX=_pre`, units xP81, yP130, vP155, vP156, vP150; `logs/score_xiii_pre.json`):
P2 and P7 meet thresholds. P1, P3, P4, P5 and P8 are inconclusive only because some development outputs were not computed for every
development model. Every available development unit passes every arm.
