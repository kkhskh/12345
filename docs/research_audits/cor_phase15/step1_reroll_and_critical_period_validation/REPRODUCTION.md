# Reproduction instructions (Investigation XIII-E)

## This package is not standalone

It reads files from earlier COR Phase 1.5 Step 1 packages, each listed with its exact sha256 in `logs/DEPENDENCIES.json` → `sibling_packages_required`:

- **Pretrained parents and natural seeds:** from XIII-B and earlier.
- **XIII-D files:**
  - base runs, with `opt_step546.pkl` used for the late branches;
  - carrier units in `checkpoints/adapt4_carrier`;
  - development outcomes.
- **Python modules:** from several earlier packages.

Place the package next to its siblings under `docs/research_audits/cor_phase15/`.

## Environment

- Python 3.13, jax/jaxlib 0.12.0.1, numpy 2.5.3, optax 0.2.8, scipy 1.18.1, all on CPU.
- `export XLA_FLAGS="--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1"`.
- Benchmark on 2 CPUs / 8 GB (`logs/BENCHMARK.json`): one 1211-step run takes about 5.5 minutes alone. Aggregate throughput is about 4 steps/s with 2–3 concurrent runs, at about 0.8 GB per run.

## Re-running

Each queue line is one command, run from the package root. Run a queue with:

`QUEUE=logs/<queue> bash scripts/lane2.sh NAME`

| workstream | queues |
|---|---|
| A | `queue_A.txt` (64 runs), then `queue_Ameasure.txt` (gated), `select_continuation.py`, `queue_Acont.txt`, `queue_Acont_measure.txt` |
| B | `queue_B.txt`, `queue_Blate.txt`, `queue_Bcont.txt`, `queue_Bmeasure.txt` (gated version `queue_Bmeasure_gated.txt`), plus `queue_Broute.txt` (descriptive) |
| C | `queue_C.txt` (`c_audit.py` per carrier unit), `c1_ideal_refs.py` |

**Scoring.** `score_A.py`, `score_B.py` and `score_C.py` (all fail-closed) take `logs/`. The preflights are `preflight_A.py`, `preflight_B.py` and `preflight_C.py`.

**Exploratory:** `logs/A_posthoc_W_features.json`.

**Dependencies:** `deps_inventory13e.py`.

## Verification

`bash scripts/verify_clean13e.sh ZIP COR_PHASE15_ROOT LOG` performs the 14 mandated checks on a clean extraction. The delivery run's output is in `logs/VERIFY_CLEAN.txt`.

## Archived checkpoints (scope)

Each run directory keeps `curve.json`, `final.json`, `stop_done.json` where written, every optimiser snapshot (`opt_step*.pkl`, needed to re-branch), and the parameter checkpoints at the steps that any analysis or verification reads: 150 (bitwise replay check), 546 (late-window branch point), 1211 (screen), 1803 and 2686 (post-review late trajectories) and 4000 (final). The other intermediate parameter saves (25–1000 except those above, 3000; about 1.1 GB, never measured) and `resume.pkl` files are excluded from the repository and the ZIP. Training is deterministic (`scripts/determinism_check.py`; step 8 of `verify_clean13e.sh` replays bit-for-bit), so any excluded checkpoint can be regenerated by re-running its command from `logs/COMPUTE_LOG.txt`.
